# Лабораторная работа №2
## Анализ веб-приложения и клиент-серверного взаимодействия

Сервис: Aviasales (https://www.aviasales.ru/)
Сценарий: поиск билетов по маршруту (Москва → Калининград)

## 1. Исследуемая информационная система

Используется тот же сервис и сценарий, что и в лабораторной работе №1: Aviasales, поиск билетов по маршруту.

## 2. Анализ HTTP-запросов

При выполнении поиска браузер отправляет несколько запросов. Основные:

| URL запроса | Метод | Относится к API |
|---|---|---|
| tickets-api.eu-north-1.aviasales.ru/search/v3.2/start | GET | Да |
| tickets-api.eu-north-1.aviasales.ru/search/v3.2/results | GET | Да |

Запрос start инициирует поиск билетов, а results периодически опрашивает сервер и забирает уже найденные варианты (механизм polling).

![Список запросов в Network](images/screenshots/step2-01.png)

## 3. Анализ HTTP-ответов

Запрос results возвращает статус 200 и тело ответа в формате JSON. В ответе содержатся данные о найденных билетах: цена, авиакомпания, время вылета и прилёта, количество пересадок.

![Ответ сервера](images/screenshots/step3-01.png)

## 4. Анализ параметров и передаваемых данных

Основные параметры маршрута передаются не в самом запросе results (https://tickets-api.eu-north-1.aviasales.ru/search/v3.2/results), а закодированы в URL страницы браузера: https://www.aviasales.ru/search/MOW0810KGD1

Расшифровка:
- MOW — код города/аэропорта отправления (Москва)
- 0810 — дата вылета (8 октября)
- KGD — код города/аэропорта назначения (Калининград)
- 1 — количество пассажиров

Запрос results регулярно опрашивает сервер и забирает уже найденные варианты билетов по идентификатору поиска, созданному ранее запросом start. Поэтому сам results не содержит параметров маршрута в URL — поиск уже запущен и привязан к сессии на сервере.

## 6. Взаимодействие Frontend, API и Backend

1. Пользователь вводит данные и нажимает «Найти билеты».
2. Интерфейс (frontend) обрабатывает действие.
3. JavaScript формирует HTTP-запрос start к API.
4. API передаёт запрос backend-серверу, который запускает поиск у партнёров.
5. Backend обрабатывает запрос, обращается к хранилищу и внешним сервисам (авиакомпании, агентства).
6. Клиентская часть периодически отправляет запрос results, чтобы забрать готовые данные.
7. Ответ (JSON) возвращается через API в браузер.
8. Интерфейс отображает результаты пользователю.

## 7. Сопоставление с лабораторной работой №1

В лабораторной работе №1 предположения о компонентах (API, сервер, хранилище, внешние сервисы) были сделаны без прямого наблюдения. В этой лабораторной работе удалось подтвердить: наличие отдельных API-запросов (start, results), формат ответа (JSON), механизм асинхронного получения результатов (polling). Новым наблюдением стало то, что параметры поиска передаются через URL страницы, а не в теле запроса. Предположительными остаются: внутреннее устройство backend и структура хранилища данных.
